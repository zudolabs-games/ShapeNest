Phase 53C — Shuffle Booster Presentation Polish
==============================================

AUDIT (pre-change flow)
-----------------------
button press → BoosterManager.TryActivate(Shuffle)
             → ShuffleBooster.ActivateShuffle()
             → TryBuildShufflePlan (gameplay, unchanged)
             → ApplyLogicalShuffle (occupancy + GridPosition preserveWorldPresentation)
             → AnimateShuffleMoves via WorldPieceMotion.AnimateHop per cell view
             → FinalizeShufflePresentation (sync world views to grid)

PRESENTATION CHANGES
--------------------
A. ShuffleBoosterButton
   - Successful activation: scale pulse 1.00 → 0.96 → 1.00 (~0.14s, unscaled)
   - Failed/busy/no-charges: subtle invalid press 1.00 → 0.97 → 1.00
   - Uses existing TweenAnimationUtility.UiPressId; restores scale on disable

B. Pre-move anticipation (ShuffleBooster + PieceView3D)
   - PlayShuffleAnticipation: mesh-only compress (~0.07s) before hops
   - XZ widen / Y squash via SetPresentationAnticipation (no root movement)

C. Movement (unchanged destinations)
   - Still uses WorldPieceMotion.AnimateHop with existing plan cells
   - Slightly tuned hop presentation params only (anticipate 0.05, lift 0.045)

D. Visual stagger
   - 25ms between independent Block units (presentation timing only)
   - Logical occupancy already applied before animation starts

E–G. Chains / nested / Ice / Shutter
   - No gameplay changes; animation still per Block unit / cell view
   - Nested inner follows outer via existing PieceView3D squash path

H. Post-arrival settle
   - PlayShuffleSettle: subtle mesh pulse (~0.06s) on moved units only

I. VFX
   - Skipped (no Shuffle-specific BoardVfx3D addition)

J. Cleanup
   - ClearShufflePresentation on ResetShuffleState / disable / interrupt
   - Kills ShapeNest.Shuffle tweens; clears squash/lift
