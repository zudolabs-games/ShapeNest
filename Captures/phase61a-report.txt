Phase 61A — Drag Movement Smoothness + Per-Cell Haptics
========================================================
Date: 2026-09-01
Unity: 6000.3.8f1 (Editor)

Root cause of movement hesitation
---------------------------------
1. Per-hop easing decelerated to near-zero velocity at each cell arrival
   (first hop EaseInOutCubic; turn hops EaseInOutSine), so the next hop
   had to re-accelerate → perceived CELL → STOP → CELL.
2. secondsPerCell=0.14 amplified that valley between hops.
3. InputManager already queues SetDragRequest while BlockMover is hopping —
   request timing / Phase 61 direction params were NOT the pause source.
4. No artificial WaitBetweenCells gate was found in BlockMover.

Timing changes (OLD → NEW)
--------------------------
- BlockMover.secondsPerCell: 0.14 → 0.105
- BlockMover.normalHopAnticipateDuration: 0.04 → 0.03
- WorldPieceMotion continuation linearWeight: 0.88 → 0.95
  (turns cruise at 0.80; softenTurn/EaseInOutSine disabled)
- WorldPieceMotion first-hop linear blend: 0.22 → 0.35

Why these values
----------------
Slightly shorter hop + less end-of-hop braking keeps consecutive cells
in a continuous velocity envelope without teleporting (still visibly animated).
