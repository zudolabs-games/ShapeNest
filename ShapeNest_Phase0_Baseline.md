## 2. Gameplay Architecture Audit

### A. Board
- **Grid Dimensions:** Dynamically resolved from `LevelData.gridWidth` / `gridHeight` (typically 5x5 or 6x6).
- **Coordinate System:** 2D integer grid `Vector2Int`. Grid origin `(0, 0)` is strictly the **bottom-left** cell. Positive X is right; positive Y is up.
- **World / UI Conversion:**
  - **Active 3D (`GridSpace3D`):** Maps logical `(x, y)` to board local `(x * pitch, surfaceY, y * pitch)` centered around the board origin. World X = grid X, World Y = elevation, World Z = grid Y.
  - **Legacy 2D (`UIGridSpace`):** Maps logical `(x, y)` to `RectTransform` anchored positions on the 2D UI Canvas.
- **Occupancy Tracking:** `BoardManager` maintains `Dictionary<Vector2Int, Block> occupancy`, `Dictionary<Vector2Int, Target> targets`, `List<ShutterState> closedShutters`, and `HashSet<Vector2Int> staticBlockedCells`.
- **Initialization:** `LevelManager.LoadLevel()` triggers `boardManager.ApplyGridSize()`, which clears occupancy and notifies `BoardPresenter3D` to generate procedural 3D tray geometry.

### B. Blocks / Shapes
- **Model Representation:** `Block.cs`. Holds `ShapeType` enum (`Square`, `Circle`, `Triangle`, `Diamond`, `Hexagon`, `Star`), `MoveDirection`, `GridPosition`, `composition` (`Simple`, `Nested`, `Chain`), and a list of `ShapeCellData` for multi-cell pieces.
- **Visuals:** Presented via `PieceView3D` in 3D (instantiated as children under `Board3D/Pieces3D`), with procedural 3D meshes generated by `ShapeVisuals3D` and `ShapeMeshFactory3D`.
- **Spawning:** `LevelManager` instantiates `Block` prefabs at coordinates specified in `LevelData.blocks`.
- **Selection:** `Block.ShowDragSelection()` and `Block.HideDragSelection()` scale and emphasize pieces on touch/pointer down.

### C. Targets / Nests
- **Model Representation:** `Target.cs`. Holds `ShapeType`, `GridPosition`, `IsMatched`.
- **Matching Criteria:** Matches when a block cell with an identical `ShapeType` lands on the target's grid coordinate while the target is unmatched.
- **Visuals:** Hollow beveled 3D ring/border meshes placed at cell elevation.
- **Consumption:** Upon match, target unregisters from `BoardManager`, plays match particles, and is deactivated/settled.

### D. Movement
- **Input System:** Unity Input System routed through `InputManager.cs` and `FingerDragController.cs`.
- **Movement Engine:** `BlockMover.cs`.
- **Constraints:** Respects `MoveDirection` (Any, Horizontal only, Vertical only, None/Fixed).
- **Collision:** Step-by-step path collision against board bounds, other blocks in occupancy, closed shutters, and static blocked cells.
- **Motion Execution:** Discrete cell-to-cell hops (`secondsPerCell = 0.105f`) with anticipation wind-up and squashes driven by `WorldPieceMotion` in 3D. Multi-cell chains translate rigidly together.

### E. Matching
- **Trigger:** Either direct arrival on a target cell during drag, or post-move auto-matching evaluated by `LevelManager.ResolveAlreadyAlignedMatchQueue()`.
- **Scope:** Cell-by-cell matching supported for multi-cell chains (`EnterChainPartialMatch`); simultaneous aligned wave matches supported via `PlayMatchingSubsetAlignedMatch`.
- **Chains:** Linked cells translate rigidly; when individual cells match their respective targets, matched cells can be extracted into nests while remaining chain cells stay playable.
- **Nested Shapes:** Inner shapes emerge and nest, followed by outer shape nesting.

### F. Level System
- **Level Loading:** `LevelManager.LoadLevel(index)` loads `LevelData` assets from `LevelDatabase.asset`.
- **Progression:** Monotonic progression stored in PlayerPrefs via `PlayerProgressManager`.
- **Win Condition:** `BoardManager.AreAllMatchesComplete()` — succeeds when all blocks and all targets are cleared/settled.
- **Failure Condition:** Countdown timer expires (`remainingSeconds <= 0`).

### G. Boosters
- **Magnet:** `MagnetBooster.cs`. A* pathfinds a soft-obstacle route from block to matching target; pulls piece into nest and consumes 1 charge.
- **Hammer:** `HammerBooster.cs`. Arms crosshair/selection; smashes selected block and corresponding target, triggering impact VFX and settling piece.
- **Undo:** `UndoBooster.cs` + `BoardUndoHistory.cs`. Restores board occupancy and piece positions to state before the last player move or shuffle.
- **Shuffle:** `ShuffleBooster.cs`. Collects all eligible unfrozen blocks and redistributes them across valid unoccupied cells.

### H. Special Mechanics
- **Ice Blocks:** `IceState.cs` + `IceView3D.cs`. Frozen blocks cannot be moved. Durability counter decrements whenever ANY match occurs on the board; thaws at 0 durability.
- **Shutters:** `ShutterState.cs` + `ShutterView3D.cs`. Multi-cell barriers covering board cells. Durability decrements on each successful board match; opens at 0 durability to reveal playable space and pieces below.
- **Fixed Direction:** `MoveDirection.Horizontal` / `Vertical` restricts pieces to single-axis sliding.
- **Nested Shapes:** Multi-tier composition (`PieceComposition.Nested`).

### I. Presentation
- **Board:** Procedural 3D rounded tray mesh generated at runtime (`BoardPresenter3D`, `BoardMeshFactory3D`).
- **Camera:** `BoardCamera3D` on `BoardCamera3D` GameObject. Orthographic/Perspective framing centered on board bounds.
- **Lighting:** Directional Key Light (`BoardKeyLight`) and Fill Light (`BoardFillLight`).
- **UI:** Managed by StarterKit UIKit under `UIController` (ScreenSpaceOverlay canvases for HUD, Level Complete, Game Over, Settings).

## 9. Recommended Rebuild Order (Phased Roadmap)

1. **Phase 1 — Visual Presentation Foundation (Toy Aesthetic):**
   - Refine 3D materials, specular highlights, and lighting to match the glossy plastic toy look of the reference.
   - Replace wireframe floor targets with sculpted concave 3D cavity sockets.
   - Add contact shadows / ground-plane depth so pieces feel grounded in the tray.
2. **Phase 2 — UI Header & Layout Polish:**
   - Implement the reference header: Top-left Restart button, top-right Settings button, pill timer badge (`⏱ mm:ss`), and clean typography.
   - Compact or stow the booster bar to give the puzzle board proper vertical framing.
3. **Phase 3 — Nesting & Match Feedback Alignment:**
   - Align piece insertion animations so pieces visually slot into female sockets with a satisfying tactile click/pulse.
   - Clarify nest occupancy vs clearing rules according to GDD.
4. **Phase 4 — Shutter & Ice Visual Polish:**
   - Add persistent frost mist VFX to ice blocks and authentic cracking feedback.
   - Implement roll-up mechanical slat animation for opening shutters.
5. **Phase 5 — Level Content & Density Enhancement:**
   - Author dense, interlocking puzzle levels using the built-in `LevelEditorWindow` and verify with `ShapeNestSolver`.
   - Support non-rectangular board perimeters (`blockedCells` / custom boundary mesh).
6. **Phase 6 — Code Cleanup & Architectural Consolidation:**
   - Decouple legacy 2D UI presentation scripts (`UIPieceView`, `UIPieceMotion`, `BoardVisual`) from `Block` and `BoardManager`.
   - Safely prune obsolete numbered `Level*.asset` duplicates.
